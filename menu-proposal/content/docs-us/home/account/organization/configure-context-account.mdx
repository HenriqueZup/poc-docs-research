## Configure Context in the Account

### **About Context**

To [**create Applications**](create-use/use-content/application/index.md) or [**Infrastructures**](create-use/use-content/infra/infrastructure.md) within a Workspace, developers **use the available Stacks**. When using these Stacks, it possible **configure the input values for the content within them, such as Plugins, Actions and Workflows**

This is where Context Configuration becomes crucial.

During the configuration and definition of Context, as an Account or Workspace Administrator, you can **predefine the input values for the content (Plugins, Actions and Workflows) in the Stacks** to standardize them and streamline the developer’s work when creating an Application. This way, they won’t need to configure the inputs themselves but only accept the predefined values. This process is called **configuring or defining contexts**.

You can set these values in three ways:

1. **As mandatory:** Values are obligatory and cannot be changed.
2. **Suggestions Only:** Developers can define the values but have the option to edit them.
3. **By environment:** Input values can vary based on the environment, such as Dev, QA, or Prod. These values can be either mandatory or suggested.


<br/>

You can configure Contexts at two levels on the StackSpot Platform:

1. **Account**: set up Contexts at the Account level, with mandatory values applied at the Workspace level, while suggested values can be modified.  
2. **Workspace**: requires using mandatory values defined in the Account Context, with the flexibility to change suggested values.


<br/>

So, **when creating an Application** within this Workspace, the developer **can configure** only **suggested values** or **not informed** in any of the Contexts.

:::tip

Ensure that your Account Context is configured by checking the details in the [**account context guide**](home/account/organization/configure-context-account.md).

:::

  <summary>Check an example of Context configuration</summary>

- **Scenario**

In a company, the Stackspot account Admin needs to configure a [**Stack**](create-use/create-content/stack/create-stack.md) with an [**Infrastructure Plugin**](create-use/create-content/plugin/create-plugin.md) for a [**Secret Manager on AWS**](https://docs.aws.amazon.com/secretsmanager/latest/userguide/intro.html). This Secret Manager is used to manage, retrieve and switch database credentials, API keys, and other Secrets for creating Applications in the company.

To do this, the Admin needs some Secret Manager parameters to be the same, to create [**Applications**](create-use/use-content/application/index.md) in the company.

<br/>

- **Solution**

To ensure uniformity in input parameters for creating Secret Manager Applications, the Admin sets up an Organization Account-level Context. The configuration includes mandatory and suggested inputs. Check the details:

- **Mandatory inputs:** The developer **cannot** change.
- **Suggested Inputs:** The developer can change suggested values.


<br/>

For this hypothetical situation, the Admin needs to follow a few steps:

1. Go to the **Account** menu;
2. Access the **Stack** Secret-Manager-Demo;
3. Access the **Infrastructure Plugin** Secret-Manager-Two.

<br/>

To configure the Context, the Admin needs to set the following Plugin input values:

<br/>

- **`Feature name`**: Microservice feature name;
- **`Microservice name`**: Microservice name;
- **`Owner team email`**
- **`Tech team email`**: Developer email responsible for the Secret Managers;
- **`KMS key Arn`**: ARN of the KMS key associated with the secret;
- **`Environment`**: Environments, e.g. Dev, QA, and Prod; and
- **`Region`**. 

<br/>

The values of **`Feature Name`**, **`Microservices name`** and **`Owner team email`** can just be suggestions. But, the Admin needs to set that the same engineer always be responsible for all Secret Managers, so this value must be set as **`Mandatory`**. 

But the **`KMS key Arn`**, **`Environment`**, and **`Region`** values are a variable depending on the situation. They can’t be a suggestion or set as mandatory.

<br/>

### **Result**

After this configuration, when a developer accesses their Workspace to create an application using the Stack Secret Manager:

- The suggested values are filled. But the Developer (Dev) can change;
- The Mandatory values are already filled. It cannot change;
- Values that have not been set can change.

:::warning  

If you have both an Account and a Workspace context configured, and neither is designated as mandatory, the Workspace context will take precedence. 

Once the Account context was set to mandatory in the initial configuration, it cannot be changed to Workspace. In this case, the account context always prevails and only changes if the context changes.

:::

This scenario **saves the developer's work time**, because they do not need to fill out all the input fields. It also ensures the same person handles the Secret Managers.

</details>

In this section, you will learn **how to configure Contexts at Account level.**

### **Steps**

Follow the instructions below to configure your Account Context:

#### Requirements

- [**Existing Stacks in your Account**](create-use/create-content/stack/create-stack.md);
- Environments configured in the account;
- Account Holder permissions.

**Step 1.** Go directly to the [**Account Portal**](http://myaccount.stackspot.com); or after [**logging into the StackSpot Portal**](https://app.stackspot.com/), click on your **profile avatar**.

**Step 2.** Select the **'Organization'** option from the displayed menu;

**Step 3.** In the Account Portal main menu, select the StackSpot EDP product and click on **'Stacks'**; 

**Step 4.** Select the Stack you want to configure the Inputs for. If it has more than one version, choose the one you want to configure the Context for;

**Step 5.** Configure the inputs of the Stack content as Contexts. To do this, access the tab corresponding to the content you want to configure, such as **'Plugins'**, for example.

:::info Additional Information  

The process for configuring the inputs of **Plugins**, **Actions** and **Workflows** as Contexts **is the same for all content types**. Simply follow the instructions below, selecting the tab corresponding to the content you want to configure.  

:::  

**Step 6.** **Select the Plugin** you want to configure the Input values;

**Step 7.** Click on the **'Input'** field. Enter its value, and specify whether it should be mandatory.

- **Select** the **'Mandatory'** checkbox, to make the value mandatory and unchangeable.
- Leave the **'Mandatory'** checkbox **unmarked** to keep the value as a suggestion.

**Step 8.** If the Input offers the option, you can also decide to **define the value per environment**:

- **Enable** the button **'Set value per environment** next to the input. Enter values for each environment and specify whether they are mandatory by clicking the checkbox.

- Leave the button **'Set value per environment'** deactivated.

**Step 9.** You can choose to [**use a Context Variable**](home/account/organization/variables/create-variables.md) to fill in the input value. To do this, click the **'Use Variable'** button next to the input and **select one of the available variables that appears in the dropdown list below the input.**

**Step 10.** After you configure all the Plugin's inputs, click **'Save'**;

**Step 11.** Now you need to publish a new version of the Stack in the Studio:

- **Step 1**: Navigate to the Studio where the Stack is published and click on it;

- **Step 2**: Click the **'New Version'** button;

- **Step 4**: Click the **'Publish'** button and fill in the following fields:
  - **Version type**: Select the **Patch** option.

## **Rules for filling in Context inputs**

- You cannot set an empty input (without a value) as mandatory.
- **Input of type `list`**: if you set this input as mandatory, all items in the list will also be mandatory. You will not be able to modify anything at levels below the Account, including values or the order of the items.
- **Input of type `object`**: by checking the "Mandatory" checkbox, only the values of the objects you fill in will be mandatory. Fields without a value can be modified. 
In the Application or Infrastructure creation flow, the user must fill in the object fields that were not configured previously.

- **Input of type `list` containing `object`**: if you define a list of objects as mandatory, **the order of the list cannot be changed, and new items cannot be added** in the Workspace. However, the fields within the objects can be altered. To set them as mandatory, fill in the values within each field. 
During the Application and Infrastructure creation process, the user will not be able to add or remove items from the main list. However, they will be able to fill in the missing fields of the internal objects that have not yet been configured.

- **Input of type `required-connection`**: at the **Account** level, it is not possible to set a Context, as it is not guaranteed that the Connection Interface will be visible to the entire Account. However, at the **Workspace** level, you can define whether the Connection Interface is mandatory or not.

## **Configuring Context values using Account Variables**

You can choose to [**use an Account Variable**](home/account/organization/variables/create-variables.md) to fill in the input value. To do this:

1. Click the **"Use variable" button** next to the input field;
2. **Select one of the available Variables** from the list that appears.

If the **value was not configured as mandatory when the Variable was created**, you can **change it** and also set it as mandatory at the Account context level.

## **Update Context values automatically**

To configure Contexts, the input values of Plugins and Actions **are configured according to the version of the Stack**. Each version can have different input values.

So, if someone publishes a new version of the Stack added to your account, the **context must be configured again**. You can do this **automatically**, just by **importing the values of the version** of the Stack that you had previously **configured**.

:::info

Only the **`name`** field is imported between Stack versions because it is the sole common field. You must configure the context for new inputs such as `user` and `port` accordingly.

:::


### **Advantages**

Updating the context values saves you from manually updating and repeating the values. This work would be extensive and repetitive if the Stack is large and has many Plugins.

For example:

1. You have configured the context of a version 1.0.0 Stack in your Account.
2. The Stack developer has created a new version, 2.0.0.
3. You receive a notice on the dashboard that you can import the values you configured in the previous version.
4. If you confirm, StackSpot will import the values into version 2.0.0. Plugins and Actions will automatically have the same values as in the previous version.

:::warning  

When a Workflow is executed, the Plugin Context is not taken into account. In other words, the Context is always that of the main Workflow, since Contexts of child Workflows or other components executed within the main Workflow are ignored.

:::

### **How it works**

When you add a new version of Stack to your Account, a notification appears on the dashboard informing you that you can import the context of previous versions. To import, follow the instructions below:

**Step 1:** Log in to your Account and click on 'Stacks' in the left side menu;

**Step 2.** In the dashboard notification or within the Stack card, click on the button **'Import input settings'** ;

![Portal screen on an account's Stacks page](/img/import-context-account-1.png)

**Step 3:** Select the version you want to import the context (the configured inputs);

![Portal screen with Stacks version selection box](/img/import-context-account-2.png)

:::tip  

Select the recommended version.

:::

**Step 4.** Click on **'Import'**.

![Portal screen with Stacks version selection box](/img/import-context-account-3.png)

You've imported the Context from a previous Stack version. Now, you can configure whatever you need.
