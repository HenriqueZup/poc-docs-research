### **stk create starter**

The **`stk create starter`** command creates a basic Starter structure. [**See how to create Starter in STK CLI**](gcreate-use/create-content/stack/create-stack-starter-cli.md#create-starter-via-stk-cli).

:::tip

The `-o`, `--target` option allows you to define a different folder name to create the Starter content. If the folder does not exist, it will be created.

If you do not use the `-o` or `--target` option, the Starter content folder name will be the same as the one you gave when creating your Starter.

:::

#### **Usage**

**Syntax**

```bash
stk create starter [NAME]
```

**Example**

```bash
stk create starter my-starter-name
```

#### **Parameters**

| **Option** | **Description** | **Example** |
| ----------- | ----------- | --- |
| `-d, --description` | Your Starter description. | <pre>stk create starter my-starter-name --description "My Starter description"</pre> |
| `-r, --remote` | Git URL to set as remote repository origin. In this case, the NAME will be defined as the Git repository name. | <pre>stk create starter my-starter-name --remote https://github.com/MyGitHubOrg/my-repository</pre> |
| `-sgi, --skip-git-init` | It will not start a Git repository. | <pre>stk create starter my-starter-name --skip-git-init</pre> |
| `-q, --non-interactive` | It does not ask for missing inputs, returning an error when required inputs are not provided. | <pre>stk create starter my-starter-name --non-interactive</pre> |
| `-o, --target` | The `-o`, `--target` option allows you to define a different folder name to create the Starter content. If the folder does not exist, it will be created. If you do not use the `-o` or `--target` option, the Starter content folder name will be the same as the one you gave when creating your Starter. | <pre>stk create starter my-starter-name --description "My Starter description" --target home/user/documents/my-stacks</pre> |
| `-t, --type` | The Starter type: 'app' | <pre>stk create starter --type app</pre> |
| `-h, --help` | Displays the command help and exits. | <pre>stk create starter --help</pre>|

### **stk list starter**

The **`stk list starter`** command lists the Starters available. You have two options:

1. List Starters from a Workspace available to your account. In this case, you must be inside a Workspace. To do this, execute the command [**stk use workspace**](home/stk-cli/commands/workspace-commands.md#stk-use-workspace) before listing the Starters.

2. List Starters outside of a Workspace. After executing the command, you need to specify the Studio and the Stack you want.

> You can access the Starter's name, type, and description. The system also notifies you if a Starter or content is deprecated with the "deprecated" tag.

#### **Usage**

```bash
stk list starter 
```

#### **Parameters**

| **Option** | **Description** | **Example** |
| ----------- | ----------- | --- |
| `-stu`, `--studio` | Filters and displays the list of Starters by the Studio. | <pre>stk list starter --studio studio-name</pre> |
| `-sta`, `--stack` | Filters and displays the list of Starters by Stack. | <pre>stk list starter --stack stack-name</pre>|
| `-t`, `--type [app/infra]` | Filter Starters by type. Accepted values are 'app' or 'infra'. |  <pre>stk list starter --type infra</pre> | 
| `-h`, `--help` | Displays the command help and exits. | <pre>stk list starter --help</pre> |

___

### **stk validate starter**

The **`stk validate starter`** command validate the structure of your Starter and it's components. The files ignored on your `.gitignore` will not be validated.

#### **Usage**

**Syntax**

```bash
stk validate starter
```

**Example**

Inside your Starter's Folder, run the following command:

```bash
stk validate starter
```

#### **Parameters**

| **Option** | **Description** | **Example** |
| ----------- | ----------- | --- |
| `-v, --verbose` | Show validation with more details. | <pre>stk validate starter --verbose</pre> |
| `-h, --help` | Displays the command help and exits. | <pre>stk validate starter --help</pre>|
