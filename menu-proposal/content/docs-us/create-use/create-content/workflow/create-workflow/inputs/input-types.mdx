## **Input Types**

Check the input types available in StackSpot Workflow. They are defined in the **`type`** field.

Type  | Value
--------- | ------
**`text`**  | String. |
**`textarea`**  | String. |
**`bool`** | Boolean. |
**`int`** | Integer. |  
**`password` | Encrypts the provided value. (string) |
**`select`** | Lists values, allowing you to select only one value (string). |
**`multiselect` | Lists values, allowing you to select one or more values (string). |
**`list`** | List of inputs of the same type (text, int, object, and required-connection). |
**`object`** | It stores a set of inputs inside an object. The object becomes a parent input with a set of child inputs. |
**`required-connection`** | It stores a set of inputs required to connect to Infrastructure inside an object. |
**`generated-connection`** | It stores a set of inputs required to provision Infrastructure inside an object. |


Check below an example of a **`workflow.yaml`** of type **`create`** with Inputs of types **`select`**, **`text`**, and **`bool`**.

```yaml
schema-version: v1
kind: workflow
metadata:
  name: create-app-node-nest-api
  display-name: Create Node/Nest API
  description: "Orchestrates the creation of an API using Node.js 22 and NestJS."
  version: 1.0.0    
spec:
  type: create   
  label: "Create Node API"
  targets:
    - app
  docs:
    en-us: docs/en_us/docs.md
    pt-br: docs/pt_br/docs.md
// new-line-start
  inputs:
    - label: "Squad Name"
      scope: default
      name: squad_name
      type: select
// new-line-end      
      help: "Enter the name of the squad responsible for the resource."
      items:
        - alpha
        - beta
        - gamma
        - delta

    - label: "Project Context (kebabcase)"
      scope: default
      name: project_context
// new-line-start      
      type: text
// new-line-end      
      required: true
      pattern: '^[a-z0-9]+(-[a-z0-9]+)*$'
      help: "Enter the project context. Example: my-project-api"

    - label: "Add MongoDB?"
      scope: default
      name: add_mongodb
// new-line-start      
      type: bool
// new-line-end      
      required: true
      default: false
      help: "Adds MongoDB dependencies."

    - label: "Add PostgreSQL?"
      scope: default
      name: add_postgresql
      type: bool
      required: true
      default: false
      help: "Adds PostgreSQL dependencies."

    - label: "Add Redis?"
      scope: default
      name: add_redis
      type: bool
      required: true
      default: false
      help: "Adds Redis dependencies."

  jobs:
    - id: job_create_app_code
      label: "Create application code"
      steps:
        - id: step_create_code
          name: fictitious-org/starter-node-nest-api@1.0.0
          type: workflow
          inputs:
            add_redis: "{{ add_redis }}"
            add_mongodb: "{{ add_mongodb }}"
            add_postgresql: "{{ add_postgresql }}"
            squad_name: "{{ squad_name }}"
            project_context: "{{ project_context }}"

    - id: job_create_app_repository
      label: "Create application repository"
      depends-on:
        - job_create_app_code
      steps:
        - id: create_git_repository
          name: fictitious-org/reusable-create-git-repo@0.0.1
          type: workflow
          inputs:
            project_id: "{{var.PROJECT_ID}}"
            project_name: "{{var.PROJECT_NAME}}"
            repository_name: "{{squad_name}}-api-{{project_context}}"

    - id: job_commit_app_code
      label: "Commit application code"
      depends-on:
        - job_create_app_repository
      steps:
        - id: step_commit_code
          name: fictitious-org/reusable-commit-git-repo@0.0.1
          type: workflow
          inputs:
            source_branch_name: "main"
            commit_message: "Automatic commit performed by StackSpot."
            repository_url: "{{ outputs.job_create_app_repository.create_git_repository.repository_url }}"

    - id: job_deploy_app
      label: "Deploy application"
      depends-on:
        - job_commit_app_code
      steps:
        - id: step_print_info
          label: "Important Information"
          type: run
          script: |
            echo "------------------------------------------- ATTENTION -------------------------------------------"
            echo " "
            echo " The application deployment must be performed through your CI/CD provider pipelines!"
            echo " "
            echo "-------------------------------------------------------------------------------------------------"
```

## **Importing Inputs from content in the Workflow**

A Workflow utilizes inputs from various types of content available in Studios, such as Plugins, Actions, and other Workflows, within its Job Steps.

To use these inputs effectively, you must manually declare the inputs for each type of content. If your Workflow executes an Action, applies a Plugin, or uses another Workflow simultaneously, you must **declare the inputs separately** for each of them.

To simplify the input process in your Workflow, you can:

- Generate an input of type **import** to consolidate all necessary inputs into a single object.
- Use the **inputs-from** option in your Workflow Steps to leverage imported inputs or an object-type input.

You **do not need** to declare each input separately.

:::warning

StackSpot **does not support** importing inputs with `scope:env (inputs-envs)`, as in the following example:

```yaml
  inputs:
    - name: name
      scope: env
```

:::

### **Input of Type `import`**

The **import** input type should be used only in StackSpot Workflows and has the following fields:

- **type:** The input type. Its value must be **`import`**.
- **from:** The reference to the inputs you want to import. The reference must follow the syntax: **'job_id.step_id'**, for example: “job_01.step_01”. The referenced Steps must be of type **‘plugin’**, **‘action’**, or **‘workflow’**.
- **label:** The text displayed in the terminal for your import input.
- **name:** The input name to identify the imported inputs.
- **includes:** **Optional** field. List to specify which inputs to import.
- **excludes:** **Optional** field. List to specify which inputs not to import.

:::caution 

If you **do not use** the **`includes`** and **`excludes`** fields, all inputs from the referenced step will be imported.

:::

Example of an import input:

```yaml title="workflow.yaml 'inputs' field"
inputs: 
  - type: import
    label: Add your bucket S3 inputs
    from: job_create_app.step_workflow_starter # steps of type action, plugin, workflow
    name: s3_starter_inputs
    includes: # Optional: import specific inputs.
      - bucket_name
      - region
    excludes: # Optional: exclude specific inputs.
      - encryption

The **`inputs-from`** field allows you to use imported inputs directly within the content of a Workflow Step. These contents can be Actions, Plugins, and Workflows executed in Steps of the same type.

:::warning

Only use **object-type** inputs in the **`inputs-from`** field. The objects you can use are:

- **Import input:** When you create an import input, it generates an object containing all imported inputs.  
- **Object** `- input`: It is an object containing all inputs from a given content.  
- Use an object-type input directly in the `inputs-from` field.  

:::

You can combine the use of imported inputs with `inputs-from` and `inputs`:

```yaml title="‘steps’ field of a workflow.yaml"
steps:
  - id: call_starter
    type: workflow
    name: stackspot-cloud/aws-s3-starter-workflow@1
    workdir: storage-infra/stackspot/{{ var.STK_WORKFLOW_EXECUTION_ID }}
    inputs-from:
      - s3_starter_inputs
    inputs:
      bucket_encryption: true # Additional or fixed inputs

Use the inputs object to send all inputs from a content to the Workflow:

```yaml title="'steps' field of a workflow.yaml"
steps:
  - id: call_starter
    type: workflow
    name: stackspot-cloud/aws-s3-starter-workflow@1
    workdir: storage-infra/stackspot/{{ var.STK_WORKFLOW_EXECUTION_ID }}
    inputs-from:
      # all inputs are passed to the called Workflow
      - inputs
```

Use an object-type input:

```yaml title="'steps' fields of a workflow.yaml"
steps:
  - id: call_starter
    type: workflow
    name: embraer-cloud/aws-s3-starter-workflow@1
    workdir: storage-infra/stackspot/{{ var.STK_WORKFLOW_EXECUTION_ID }}
    inputs-from:
      # all fields from the object_input are passed to the called Workflow
      - object_input
```
