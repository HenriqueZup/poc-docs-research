## **What is StackSpot EDP?**

EDP stands for Enterprise Developer Platform. It is the part of the StackSpot platform designed to create, standardize, organize, and deploy Applications and Infrastructures.

In StackSpot EDP, **companies** can create and distribute reusable, standardized technology packages (called Stacks) — such as Plugins and Actions — in a centralized way.

This ensures efficiency through the standardization and reuse of Content, especially Stacks.

### **Where to access StackSpot EDP?**

You can access StackSpot EDP in two ways:

- [**StackSpot Portal**](https://app.stackspot.com/): web interface to manage and use all Platform resources.
- [**STK CLI**](home/stk-cli/install.md): command-line tool to create, configure, and automate tasks.

To get started,
- Log in with your company email.

> If you are unable to log in and are part of a company, contact the person responsible for the StackSpot Account in your organization to request access and permissions.

## **StackSpot Fundamentals**

Imagine StackSpot EDP as a toy made up of various building blocks that can be assembled to create different objects. Each set and type of block can be compared to the technologies used to develop software:

1. **Studio = Toy box**

The Studio is a box that stores the blocks, where the various groups of blocks are gathered. These pieces are the Plugins and Actions. In addition to these contents, there are the Stacks, which are responsible for organizing the Plugins, Actions, and Starters.

<br/>

![](/img/studio.png)

<br/>

2. **Plugin = Building blocks**

It is one of the blocks that represent application source code, which can be part of them, a base, or even a complete Application. It can be of two types: App for Applications that involve business rules such as a CRUD, and Infra for Infrastructure resources generated by Terraform/IaC, such as a database.

It is a building block piece that can be fitted into different constructions to add new functions. For example, a window, a door, or a wheel. In StackSpot, App Plugins help create Applications, and Infra Plugins assist in creating Infrastructures. The code for Applications and Infrastructures is precisely in the Plugins.

<br/>

![](/img/plugin.png)

- **Action**

It is a building block that represents a script. This script executes automations for your project and can be written in Python or Shell.

<br/>

![](/img/action.png)

<br/>

3. **Stack = Ordered set of technologies**

The Stack represents a "bucket" full of pieces organized for a common and specific purpose. It is a grouping where you have everything you need to assemble various types of constructions already separated by theme or utility, such as an Angular or Java Stack, which, when used, will create a complete Front-end or Back-end Application.

<br/>

![](/img/stack.png)

<br/>

4. **Starter = Different ways to use the Stack**

The Starter is the "instruction manual" that comes with the building block bucket, that is, the Stack. The Starter is a manual for each category that exists in the Stack, and from it, you create an object, such as Applications and Infrastructures.

<br/>

![](/img/starter.png)

<br/>

5. **Workflow: a manual that orders how you should assemble each piece**

The Workflow is the process of following the manual and fitting the pieces together until everything is ready. It is the flow followed to transform loose pieces into something functional. In StackSpot, the Workflow defines the order in which the contents (Actions and Plugins) are executed to generate the resources the user requested in the StackSpot EDP Portal, such as Create App or Create Infra, for example.

<br/>

![](/img/workflow.png)

<br/>

6. **Application/Infrastructure: a finished toy**

The final result is the generation of your Application or Infrastructure. Just like with building block pieces, this is the moment to see the finished toy, working and ready to be used by others.

<br/>

![](/img/app-infra.png)

<br/>

### **Content Hierarchy**

There are contents that can be created within a [**Studio**](create-use/studio/create-studio.md), see below:

- Stacks;
- Plugins;
- Actions;
- Starters.

All content is inside a Stack, which works as an organizer or content package. Starters are different ways to use this package. For example, you can have a Starter that creates an Application with a database or another that creates one without a database. This way, you choose the option that best suits your needs.

<br/>

![](/img/contents.png)

## **Journeys in StackSpot EDP**

## **Content Creator**

The content creator in StackSpot is the one who creates Plugins, Actions, and Stacks.

### **Prerequisites**

Have an account in:
- [**StackSpot EDP Portal**](https://stackspot.com/): have an Account with specific permission for **content creation**.
- Have an active account in your Organization's SCM (GitHub, Gitlab, Azure).

Installed on your machine:
- **STK CLI**: required to integrate with StackSpot EDP.
- **VS Code and the SDK of the programming language you will use to create the code**.

![](/img/edp-creator-flow-pt.png)

### **Essential concepts for the Creator**

#### **Connection Interface**

Connection Interfaces are parameters of an AWS resource that enable its connection with other resources on the Platform.

Each AWS service has different attributes in the Connection Interface registration, created when deploying the Infrastructure generated through the platform. This way, any Infrastructure or Application compatible with the Connection Interface contract can connect to it.

![](/img/connection-interface.png)

#### **Self-Hosted**

Self-Hosted is an option that allows you to use StackSpot EDP running on your company's own servers instead of using StackSpot's cloud infrastructure.

In other words, instead of relying on the environment managed by StackSpot, you can install and run the Platform within your own environment (on-premises or private Cloud).

> This configuration is done only by the SRE.

![](/img/Desk-Systemcontext1-PT-Dark.png)

## **Content Consumer**

The Content Consumer is the one who uses the content created and made available by the Creators, represented by the Developer/Software Engineer and Tech Leads.

If you use StackSpot to develop Applications or Infrastructures, you are using content such as Plugins and Actions grouped in Stacks, all standardized and published in Studios.

This way, you can focus on the functionalities of your Application or Infrastructure by using these pre-configured technology pieces provided by your organization's platform architects (Content Creators).

> You can only use the content available in the Stacks.

### **Prerequisites**

Have an account in:
- [**StackSpot EDP Portal**](https://app.stackspot.com/): have an Account with permission to use the Content.
- Have an active account in your Organization's SCM (GitHub, Gitlab, Azure). (Check with your Account administrator).

Installed on your machine:

- **VS Code and the SDK of the programming language you will use to create the code**.

### **1. Creating your Application or Infrastructure**

An Application (App) and an Infrastructure (Infra) are created in flows with similar steps, as in the example below:

**Step 1.** Select the Workspace where you will create your Application or Infrastructure;

> To create an App or Infra you need a Workspace.

<br/>

**Step 2.** Select the Stack (and its version) and choose a Starter;
**Step 3.** Add a name and description for your App or Infra;
**Step 4.** Select or create a repository;
**Step 5.** Add App or Infra type Plugins.

See the image below for a representation of this Application and Infrastructure creation flow in StackSpot EDP:
