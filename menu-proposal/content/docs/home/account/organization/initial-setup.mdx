## **Pré-requisitos**

[**Você precisa ter permissão de Account Holder para continuar com essas configurações**](home/account/organization/access-management/roles.mdx ).

Siga os passos a seguir:

### **Passo 1. Ativar a Conta da sua Organização**

**1.** Acesse o [**portal da Conta StackSpot**](http://myaccount.stackspot.com) e faça o login com o e-mail da sua organização.

**2.** Em seguida, você receberá um convite para fazer login e acessar a Conta.

**3.** Depois de fazer login, selecione a opção **'Organização'** no menu principal para acessar as configurações da Organização. 


> Se você ainda não tem uma conta da StackSpot EDP, [**entre em contato com nosso time e agende uma demo**](https://use.stackspot.com/agende-demo-pt-site).

### **Passo 2. Configurar SSO (Single Sign-On)**

Você pode configurar a integração com o provedor de identidades da sua empresa. Isso é necessário para qualquer usuário faça o login via SSO da sua organização pelo [**Portal da StackSpot EDP**](https://app.stackspot.com/login).

[**Para mais detalhes, confira os passos no guia SSO**](home/account/organization/sso-group-mapping/sso-configuration.mdx) 

### **Passo 3. Integrar o SCM (Source Code Management) na Conta**

A integração do seu <Tooltip text="Source code management (SCM) rastreia alterações em um repositório de código, mantendo um registro de modificações e auxiliando na gestão de conflitos que surgem ao integrar atualizações de diferentes colaboradores.">SCM</Tooltip> com a StackSpot traz alguns utilitários para as equipes e podem ser executados remotamente via pipeline de CI/CD.
[**Siga os passos na seção de Integrar o seu SCM na Conta**](home/account/organization/scm-integration/index.mdx)

### **Passo 4. Cadastrar ambientes**

Você precisa cadastrar ambientes quando usar a sua própria conta cloud na StackSpot. Os ambientes são usados pelas pessoas desenvolvedoras para criar os conteúdos dentro dos Workspaces, como Aplicações, Infraestruturas, Connections Interface, etc.

[**Siga os passos na seção Criar Ambientes**](home/account/organization/create-env.mdx)


### **Passo 5. Configurar o Deployment para sua Organização** 

Essa configuração é feita via Runtime Self-Hosted. Para configurar, confira o [**guia de configuração de Runtime Self-hosted**](deployment/deploy/use-self-hosted/index.mdx).  

:::caution Atenção! 
Caso a sua Conta tenha sido criada **antes de 2024**, o deploy ainda pode ser feito via **Engine de Deploy da StackSpot EDP**. 

Então, você precisa configurar sua Conta Cloud dentro do seu Workspace. Para ver como configurar cada provedor, acesse:

- [**Configurar Conta Cloud AWS**](home/workspace/config-cloud-account.mdx);
- [**Configurar Conta Cloud Azure**](home/workspace/config-cloud-account-azure.mdx);

Para conferir informações sobre esse modelo de deploy, [**confira a seção StackSpot Deploy Engine**](deployment/runtime-engine/intro-runtime-engine.mdx). 

::: 

### **Passo 6. Criar grupos de permissão e adicionar membros na Conta**

Agora, crie Grupos definir as permissões de cada membro dentro da sua Conta. Confira o guia [**como criar grupos**](home/account/organization/access-management/groups.mdx).

Pronto, você fez as configurações iniciais da sua conta. Confira os próximos passos:

### **Próximos passos**

- [**Criar Estúdio**](create-use/studio/create-studio.mdx): é no Estúdio onde os membros da sua conta podem criar conteúdo na StackSpot. Este conteúdos são Plugins, Stacks, Starters e Actions.
- [**Criar Workspace**](home/workspace/create-workspace.mdx): sua conta precisa ter Workspaces para utilizar os conteúdos criados no Estúdio para criar Aplicações e Infraestruturas.
- [**Configurar Contexto na Conta**](home/account/organization/configure-context-account.mdx): depois que sua Conta tiver Stacks criadas, você pode configurar **Contextos**. São configurações prévias de valores de inputs de plugins e outros recursos de uma Stack para **padronizar** ou **agilizar a criação** de Aplicações e Infraestruturas na StackSpot.
