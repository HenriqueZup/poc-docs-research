### **stk ai**

O comando **`stk ai`** inicia o [**Assistente de Inteligência Artificial da StackSpot**](https://www.stackspot.com/pt/ai) em seu terminal.

#### **Uso**

Execute o comando para inicializar o assistente:

```bash
stk ai
```

Em seguida, faça perguntas no prompt para o assistente.

- Para acessar a ferramenta de análise de código. Insira '`code`' no seu prompt e cole o código fonte para ser revisado;
- Insira '`exit`' ou 'Ctrl+c' para encerrar sua sessão.


#### **Parâmetros**

| **Opção** | **Descrição** | **Exemplo** |
| ----------- | ----------- | --- |
| `-oc`, `--only-code` | Use está opção para gerar somente o código sem explicações do agente. | <pre>stk ai code [your prompt here] --only-code</pre>
| `-o`, `--output` | Define um arquivo para gravar o código de saída do prompt. | <pre>stk ai code [your prompt here] --output file.txt</pre> | 
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk ai --help</pre>|

### **stk configure connection**

:::warning Atenção!
O comando **`stk configure connection-interface`** vai ser depreciado e não será mais utilizado, ele foi atualizado para **`stk configure connection`** .
::: 

O comando **`stk configure connection`** possibilita editar as configurações da Connection exigida ao aplicar um Plugin de **app** ou **infra**.

- A Connection requerida já deve estar cadastrada.

#### **Uso**

**Sintaxe**

```bash
stk configure connection [OPÇÕES] [CONNECTION-ALIAS]
```

> Você pode configurar as Connection que aparecem na lista do Portal.

**Exemplo**

```bash
stk configure connection-interface <connection-alias> --plugin <studio>/<stack>/<plugin>@<version> --new-value <connection-to-select>
```

#### **Parâmetros**

| **Opções** | **Descrição** | **Exemplo** |
| ----------- | ----------- | --- |
| `-a, --alias` | Alias do Plugin que será configurado. | <pre>stk configure connection my-conn-alias1 --alias my-plugin-alias -nv my-conn-alias2</pre> |
| `-nv, --new-value` | Informa o nome da nova Connection. | <pre>stk configure connection my-conn-alias1 --alias my-plugin-alias --new-value my-conn-alias2</pre> |
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk configure connection --help</pre>|

### **stk create extension**

O comando **`stk create extension`** cria a estrutura de uma Extensão customizável para a StackSpot EDP com o STK CLI. Você deve adicionar o código da sua Extensão nessa estrutura.

#### **Uso**

Para criar uma extensão, você precisa executar o comando **`stk create extension`** e informar os dados da sua Extensão:  

- Nome da Extensão;
- Descrição para a Extensão;
- Nível em que sua Extensão será visível. As opções disponívels são os níveis de **Organização** ou **Workspace**;
- Caminho da pasta onde você vai adicionar o código da sua extensão. 

**Sintaxe**

```bash
stk create extension [OPÇÕES] [NOME]
```

**Exemplo**

```bash
stk create extension dashboard-extension --level workspace
```

#### **Parâmetros**

| **Opções** | **Descrição** | **Exemplo** |
| ----------- | ----------- | --- |
| `-r`, `--remote GIT-REMOTE-URL` | URL de um repositório Git como origem do repositório de uma Extensão. Obrigatório quando o valor `NOME` não é informado na Extensão, neste caso o valor do `NOME` será definido como o nome do repositório Git informado. | <pre>stk create extension --remote https://github.com/my-gh-organization/my-extension-repository</pre>|
| `-sgi`, `--skip-git-init` | Não inicia um repositório Git na pasta da Extensão. | <pre>stk create extension my-extension-name --skip-git-init</pre>|
| `-d`, `--description` | Descrição que explique o propósito e uso da sua Extensão. | <pre>stk create extension my-extension-name --description "Creating my first StackSpot EDP Extension."</pre>|
| `-l`, `--level` | Configura os níveis em que a Extensão ficará disponível. Os níveis aceitos são: `organização` ou `workspace`. | <pre>stk create extension my-extension-name --description "Creating my first StackSpot EDP Extension." --level workspace</pre>|
| `-p`, `--path` | Caminho relativo para a pasta de distribuição. A pasta de distribuição (`dist`) é a pasta que contém o código otimizado e pronto da sua Extensão para ser usado em produção. A pasta de distribuição é gerada pelo processo de construção do projeto (`project build`).  | <pre>stk create extension my-extension-name --description "Creating my first StackSpot EDP Extension." --level workspace --path /project/dist</pre>|
| `-q`, `--non-interactive` | Não pergunta ao usuário os parâmetros de entrada, retornando um erro caso algum parâmetro obrigatório não tenha sido fornecido. | <pre>stk create extension my-extension-name --description "Creating my first StackSpot EDP Extension." --level workspace --non-interactive</pre>|
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk create extension --help</pre>|

### **stk deploy plan**

O comando **`stk deploy plan`** gera um arquivo de manifesto (`manifest.yaml`) usado para planejar a implantação de uma Aplicação ou Infraestrutura.

Antes de executar o comando você deve:

1. Fazer o login na sua Conta com o comando [**stk login**](#stk-login).
2. Estar com um Workspace ativo, acesse um Workspace com o comando [**stk use workspace**](home/stk-cli/commands/workspace-commands.md#stk-use-workspace).

#### **Uso**

```bash
stk deploy plan --env env_name
```

#### **Parâmetros**

| **Opções** | **Descrição** | **Exemplo** |
| ----------- | ----------- | --- |
| `-e`, `--env`| Define o nome do Ambiente que será usado para executar o deploy da Aplicação. Consulte os Ambientes disponíveis em seu Workspace através do comando [**stk list env**](#stk-list-env). | <pre>stk deploy plan --env qa</pre> |
| `-o`, `--target` | Caminho onde o arquivo manifest.yaml será gerado. Por padrão será gerado na pasta atual. | <pre>stk deploy plan --env qa --target /home/user/app</pre> | 
| `-v`, `--version`  | Define a versão da tag de deploy. Você deve usar o padrão de versionamento semântico. Exemplo: "1.0.0" | <pre>stk deploy plan --version 1.0.0</pre> |
| `-b`, `--branch` | Nome da branch do Git que será usada no deployment. **Opcional**.| <pre>stk deploy plan --branch app2-last-release</pre> |
| `-r`, `--repo` | URL do repositório que será validado com o repositório registrado no manifesto da Aplicação/Infraestrutura.  | <pre>stk deploy plan --env development --repo https://github.com/my-org-name/org-repo-name</pre> |
| `--open-api-path`  | Caminho para o arquivo Open API relativo à raiz do repositório Git. **Opcional**. | <pre>stk deploy plan --open-api-path API/my-app-folder</pre> |
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk deploy plan --help</pre> |

### **stk deploy status**

O comando **`stk deploy status`** monitora e exibe o status do deploy da sua aplicação ou infraestrutrua em execução.

Antes de executar o comando você deve:

1. Fazer o login na sua Conta com o comando [**stk login**](#stk-login).
2. Estar com um Workspace ativo, acesse um Workspace com o comando [**stk use workspace**](home/stk-cli/commands/workspace-commands.md#stk-use-workspace).

#### **Uso**

```bash

```

:::info
O ID do deploy fica localizado arquivo **stk.yaml** da aplicação ou infraestrutura, dentro do campo **spec:** nos atributos **app-id** ou **infra-id**.
:::

#### **Parâmetros**

| **Opções** | **Descrição** | **Exemplo** |
| ----------- | ----------- | --- |
| `-w`, `--watch`  | Monitora e exibe no terminal o status do deploy automaticamente. | <pre>stk deploy status STATUS_ID --watch</pre> |
| `-r, --report` | Gera um relatório de status com o tipo de arquivo informado. Os tipos de arquivo suportados são: **`json`** ou **`md`**. | <pre>stk deploy status STATUS_ID --watch --report json</pre> ou <pre>stk deploy status STATUS_ID --watch --report md</pre>| 
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk deploy status --help</pre> |

### **stk diff state**

O comando **`stk diff state`** compara o status do deployment de uma Aplicação ou Infraestrutura entre um ambiente alvo e um ambiente origem e exibe no terminal as diferenças que existem entre os ambientes.

#### **Uso**

1. Ative o uso de um Workspace com o comando [**stk use workspace**](home/stk-cli/commands/workspace-commands.md#stk-use-workspace).
2. Execute o comando dentro da pasta da Aplicação ou Infraestrutura, em seguida informe o(s) nome(s) do(s) ambiente(s) que você deseja consultar. 
3. Ao desabilitar o highlight do texto da comparação exibida no terminal, os seguintes símbolos são apresentados das linhas alteradas:

- **---**: Representa um trecho removido.  
- **+++**: Representa um trecho adicionado.  
- **^^^**: Representa um trecho alterado.

**Sintaxe**

Por padrão, o comando compara as diferenças da Aplicação ou Infraestrutura especificadas em  **`TARGET_ENV`** com aquelas do seu ambiente **local**:

```bash
stk diff state [TARGET_ENV]
```

Para informar o nome do ambiente de origem que você deseja, use a opção **`--origin-env`**. 

```bash
stk diff state [TARGET_ENV] --origin-env [ORIGIN_ENV]
```

**Exemplo**

Comparação do estado de uma Aplicação local com a Aplicação do ambiente de produção (**`production`**):

```bash
stk diff state production
```

Comparação do estado de uma Aplicação do ambiente de desenvolvimento (**`development`**) com a Aplicação no ambiente de produção (**`production`**):

```bash
stk diff state production --origin-env development
```

Para desabilitar o destaque (highlight) exibido no terminal, use a opção **`--highlight-disable`**:

```bash
stk diff state development --highlight-disable
```

#### **Parâmetros**

| **Opções** | **Descrição** | **Exemplo** |
| ----------- | ----------- | --- |
| `-o, --origin-env` | Define o ambiente utilizado no deployment da Aplicação ou Infraestrutura. Você deve informar o nome do ambiente desejado. O valor padrão é **‘local’** para comparar a Aplicação ou Infraestrutura da pasta local atual.  | <pre>stk diff state development --origin-env production</pre>|
| `--hd, --highlight-disable` | Desabilita o destaque (highlight) das diferenças exibidas no terminal. | <pre>stk diff state development --highlight-disable</pre>| 
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk diff state --help</pre>|

### **stk init**

O comando **`stk  init`** é utilizado na inicialização e configuração da ferramenta STK CLI no seu ambiente. O comando mostra uma lista de todos os parâmetros disponíveis, além de permitir configurar o proxy e desabilitar os certificados.

Os usuários com a VPN privada devem configurar os parâmetros manualmente.

#### **Parâmetros**

Confira as opções disponíveis no comando:

| **Opções** | **Descrição** | **Exemplo** |
| :--- | :--- | --- |
| `-k ou --disable-ssl-verify` | Desabilita a verificação de certificados SSL. É usado quando o proxy nos ambientes de VPN privada retornam certificados inválidos para o Github.| <pre>stk init --disable-ssl-verify</pre> |
| `-p ou --proxy <host>:<port>` | Configura um proxy para realizar as conexões HTTP. | <pre>stk init --proxy proxy.mycorp:8080</pre> |
| `-c ou --clean` | Limpa as configurações feitas anteriormente. É usada para remover configurações padrão. | <pre>stk init --clean</pre> |
| `-e ou --proxy-exclusions <url-proxy1>,<url-proxy-2>` | Define a lista de URLs, separadas por vírgula, que não devem se conectar via proxy configurado. | <pre>stk init --proxy-exclusions proxy.mycorp1.com, proxy2.mycorp.com, proxyn.mycorp.com</pre>|
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk init --help</pre>|

### **stk login**

O comando **`stk login`** realiza o login em uma conta StackSpot. Você precisa informar o e-mail da sua conta StackSpot. A partir disso, o comando abre o seu navegador e pede pelo preenchimento de seus dados e a confirmação de acessos para gerar uma sessão.

#### **Uso**

```bash
stk login [EMAIL]
```

#### **Parâmetros**

|**Opções** | **Descrição** | **Exemplo** |
| --- | --- | --- |
| `EMAIL` | E-mail utilizado para fazer o login na conta StackSpot. | <pre>stk login mystackspot-account@email.com</pre>|
| `-id`, `--client-id` | ID do cliente gerado no site da StackSpot. | <pre>stk login mystackspot-account@email.com -id [ID value] -key [Client Key value]</pre> |
| `-key`, `--client-key` | Chave do cliente gerada no site da StackSpot. | <pre>stk login mystackspot-account@email.com -id [ID value] -key [Client Key value]</pre> |
| `-r`, `--realm` | Domínio da organização StackSpot do cliente. | <pre>stk login mystackspot-account@email.com -id [ID value] -key [Client Key value] -r [Client realm name]</pre> |
| `-a`, `--account-type` | Define o tipo de conta para o login. As opções disponíveis são: `enterprise` ou `personal`. | <pre>stk login mystackspot-account@email.com --account-type personal</pre> |
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk login --help</pre> |

- **Username:** nome de usuário e/ ou email cadastrado. Exemplo: `john.doe@github.com`.
- **Email:** endereço de email da conta. Exemplo: `john.doe@github.com`.
- **Account:** nome da sua conta StackSpot. Exemplo: `John Doe`.
- **Account Slug:** slug da sua conta. Exemplo `john-doe`.
- **Account Type:** o tipo da sua conta. Exemplo: `enterprise`.
- **Realm:** domínio da sua conta StackSpot. Exemplo: `github`.
- **Start session:** data de início da sua sessão. Exemplo: `2024-01-18 10:24:40`.
- **Expiration session:** data de expiração da sessão. Exemplo: `2024-01-18 11:24:40`.
- **Expiration refresh:** data de renovação da sessão. Exemplo: `2024-01-18 19:24:40`.

#### **Parâmetros**

| **Opções** | **Descrição** | **Exemplo** |
| ----------- | ----------- | --- |
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk show me --help</pre>|

### **stk update api-definition**

O comando **`stk update api-definition`** atualiza a especificação OpenAPI da sua API publicada na StackSpot.

#### **Uso**

**Sintaxe**

```bash
stk update api-definition [API_ID]
```

**Exemplo**

```bash
stk update api-definition AJDt2A5pe2T
```

#### **Parâmetros**

| **Opções** | **Descrição** | **Exemplo** |
| ----------- | ----------- | --- |
| `-e, --env` | Nome do ambiente da API que será atualizado. | <pre>stk update api-definition AJDt2A5pe2T --env prod</pre>|
| `-c, --contract` | Caminho para o arquivo da especificação OpenAPI. | <pre>stk update api-definition AJDt2A5pe2T --contract home/user/my-apis/openapi-specs/api-spec.yaml</pre>|
| `-g, --gateway-url` | Define URL base da API. | <pre>stk update api-definition AJDt2A5pe2T --env hom --gateway-url</pre>|
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk update api-definition --help</pre>|

### **stk update doc**

O comando **`stk update doc`** atualiza a documentação de uma Action, Stack ou Plugin.

#### **Uso**

**Sintaxe**

```bash
stk update doc [STUDIO-SLUG]
```

Dentro da pasta da sua Stack, Plugin ou Action, execute o comando:

**Exemplo**

```bash
stk update doc
```

#### **Parâmetros**

| **Opções** | **Descrição** | **Exemplo** |
| ----------- | ----------- | --- |
| `-s, --studio` | O nome do Estúdio que terá a Stack, Plugin ou Action atualizados. | <pre>stk update doc --studio my-studio-slug</pre>|
| `-v, --verbose` | Apresenta a atualização da documentação com mais detalhes.| <pre>stk update doc --verbose</pre>|
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk update doc --help</pre>|

### **stk upgrade**

O comando **`stk upgrade`** atualiza a versão do STK CLI quando há uma nova disponível.


#### **Uso**

Para atualizar o STK CLI, execute no terminal o comando **`stk upgrade`**:

```bash
stk upgrade
```

Se houver uma nova versão disponível, a seguinte mensagem será exibida no terminal:

```bash
Your STK CLI version 4.0.0 is outdated. The new version 4.1.0 is available.
To upgrade run the command: 'stk upgrade'.
```

#### **Parâmetros**

| **Opções** | **Descrição** | **Exemplo** |
| ----------- | ----------- | --- |
| `--force` | Força o STK CLI a fazer o upgrade para uma nova versão principal | <pre>stk upgrade --force</pre> |
| `-h`, `--help` | Exibe a ajuda do comando e sai. | <pre>stk upgrade --help</pre>|

Uma nova versão principal, também conhecida como versão **`major`**, traz mudanças em relação à versão anterior. Essas mudanças causam incompatibilidade entre as versões e impossibilita que você retorne para a versão anterior.

Se uma versão **`major`** está disponível, ao fazer a atualização, o STK CLI apresenta um aviso de incompatibilidade e disponibiliza o parâmetro **`--force`** para que você atualize a versão.
