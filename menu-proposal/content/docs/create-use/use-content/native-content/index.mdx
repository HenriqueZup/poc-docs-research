Os conteúdos nativos da StackSpot, são Actions e Workflows, e obrigatórios para o uso da plataforma. Para simplificar sua utilização, esses conteúdos estão disponíveis em um Estúdio oficial gerenciado pela StackSpot.

Os conteúdos foram transferidos de repositórios públicos para o Estúdio **stackspot-core**. Esses conteúdos agora são privados e não estarão visíveis para os usuários na plataforma.

## **Migração dos conteúdos**

Com a migração dos conteúdos, não é mais necessário clonar os repositórios e republicá-los em seus Estúdios. Agora, você pode usar as Actions e Workflows diretamente pelos comandos do STK CLI.

Para executar uma Action ou Workflow, você agora deve usar o Estúdio Qualifier **stackspot-core** e o nome do conteúdo desejado. Confira os exemplos a seguir:

- **Action**: **`stk run action stackspot-core/nome-slug-action`**;  
- **Workflow**: **`stk run workflow stackspot-core/nome-slug-workflow`**;

:::warning Atenção !

O comando stk run workflow é usado apenas para executar Workflows do tipo reusable. Para executar outros tipos de Workflows, utilize comandos específicos que aceitam o parâmetro --workflow. Por exemplo, para executar um Workflow de deploy, use o comando stk deploy.

```bash
stk deploy app --workflow stackspot-core/nome-slug-workflow-deploy-app
```

:::

### **StackSpot Actions**

Actions da própria StackSpot que foram migradas para o Estúdio.

#### **Configurar SCM**

StackSpot Action que executa a criação de repositórios e configura o Workflow nos serviços de [**SCM (Source Code Management), GitHub, GitLab, Azure e Bitbucket**](home/account/organization/scm-integration/index.mdx) para integrar com a plataforma da StackSpot:

```bash
stk run action stackspot-core/setup-scm@1.0.0
```

[**Para detalhes da Action, acesse a documentação setup-scm**](create-use/use-content/native-content/action-setup-scm.mdx).
